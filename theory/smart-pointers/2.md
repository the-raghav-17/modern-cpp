- There is a critical flaw with the code that we wrote in 1.cpp. If we create a pointer that points to the same resource, and accidentally free it, it will lead to a double free() bug.

```cpp
int main()
{
    My_ptr<Resource> ptr{ new Resource() };
    My_ptr<Resource> ptr2{ ptr };

    // The allocated resource will get freed twice;
    // once when ptr2 exits the scope and once when
    // ptr exits the scope
}
```

or a similar problem will occur in a case like this
```cpp
void some_fun(My_ptr<Resource> ptr)
{
}

int main()
{
    My_ptr<Resource> ptr{ new Resource() };
    some_fun(ptr);
}
```

Here when passing `ptr` to `some_fun`, a copy is created that points to the same resource. This means that the ptr inside of `some_fun` will destroy the resource when it exits. And when the ptr inside main also exits, it also tries to delete the same memory, thus leading to undefined behavior.
